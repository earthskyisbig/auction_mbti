# 웹 화면 빌드

JSON 데이터 계약을 받아 **초보자가 혼자 끝까지 갈 수 있는** 단일 HTML을 만든다. 서버·수집 없음.

## 1. 화면 구조 (고정)

```
[시작]  무엇을 하는지 3단계로 설명 + "정답이 없습니다" 안내
  ↓
[1단계] 내 조건 4가지 — 예산(구간 버튼) · 지역(시도+시군구, 규제 자동판정 배지) · 주택 보유 수 · 경매 경험
  ↓
[2단계] 성향 질문 9개 — 한 화면에 한 질문, 선택지 2개, 진행바, 이전 가능
  ↓
[3단계] 결과
        ├ 경고 배너 (danger → warn → info 순 정렬)
        ├ 유형 코드·이름·요약·키워드 + 축 3개(2:1이면 "약간 기울어짐")
        ├ 잘 맞는 물건 / 가장 큰 함정
        ├ ★ 검색조건 표 + 사이트 따라 하기 1~6 + 계산 근거 접기
        ├ 입찰 전 체크리스트(체크박스) + 지금 당장 할 일
        └ 다시하기 / 검색조건 복사 / 인쇄 + 면책
```

**결과 화면의 주인공은 유형 이름이 아니라 검색조건이다.** 진단만 받고 끝나면 아무 소용이 없다.

## 2. 데이터 주도

문항·유형·플래그를 로직에 하드코딩하지 않는다. `02_diagnostic.json` 구조(`axes`/`questions`/`facts`/`types`/`flags`)를 그대로 인라인 객체로 임베드하고 렌더링한다. 데이터가 바뀌어도 로직은 그대로여야 한다.

단일 파일 유지를 위해 `fetch` 대신 `<script>` 인라인 임베드를 쓴다(경로 의존 제거).

## 3. 계산은 JSON이 정본

`04_search_criteria.json`의 규칙을 그대로 JS로 옮긴다:

```
가격상한 = equity_top × ltv_mult[지역][보유수] × 예비비계수(H 0.85 · R 0.9)   → 만 원 단위 내림
유찰     = 1 + (R) + (P) + (규제) − (S·E이고 예산 1.5억 초과), 최소 0
권리     = R ? special_ok : safe   (단 초보+R → safe로 하향 + danger 배너)
물건종류 = 출구별 기본 → 예산 보정(5천↓ 아파트 제외 / 3억↑ 다세대 제외)
면적     = K 또는 5천↓ ? 59㎡ 이하 : 59~84㎡
```

**골든 케이스 4건과 원 단위까지 일치**시킨다. 불일치면 JSON이 아니라 JS를 고친다.

## 4. 초보 사용성 (타협 금지)

- 선택지는 **2개**. 4개면 고민이 길어지고 이탈한다.
- 금액은 직접 입력이 아니라 **구간 버튼**.
- 규제지역은 **묻지 않고 지역에서 자동 판정**해 배지로 알려준다.
- 전문용어에는 괄호 설명: 명도(살고 있는 사람 내보내기), 유찰(입찰자가 없어 다음 기일로 넘어가며 가격이 20~30% 내려감).
- 유찰 0회는 "0회 이상"이 아니라 **"제한 없음(신건도 포함)"**으로 표기한다.
- 검색조건 **복사 버튼**을 둔다.
- 모바일 세로 화면 기준으로 설계한다.
- 가격 상한 옆에 항상 **"검색 범위일 뿐 입찰가 상한이 아님"**을 붙인다.

## 6. 산출물 & 검증

- `index.html` (프로젝트 루트) + 동일 내용 `부동산투자성향테스트.html`. **두 파일은 항상 같은 내용.**
- 검증은 반드시 로컬 서버로:

```bash
python -m http.server 8899      # file:// 은 브라우저 자동화가 막힌다
```

브라우저에서 (1) 골든 케이스 4건 계산 대조, (2) 8유형 전부 도달 가능, (3) 초보+모험형에서 배너·하향 확인, (4) 결과 HTML에 `undefined`가 없는지, (5) 콘솔 에러 없음을 확인한다.
