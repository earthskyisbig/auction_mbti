# 유형 콘텐츠 작성

각 유형이 "내 얘기"로 읽히게 쓰고, **그래서 무엇을 확인하고 무엇부터 할지**로 연결한다. 마케팅이 아니라 **본인 판단 도구**다.

## 카드 구조 (`02_diagnostic.json`의 `types[]`와 1:1)

| 필드 | 내용 | 분량 |
|---|---|---|
| `summary` | 정체성 | 2~3문장 |
| `keywords` | 결과 화면 칩 | 4개 |
| `fit` | 잘 맞는 물건 | 3개 |
| `trap` | 가장 큰 함정 | 2~3문장 |
| `checklist` | 입찰 전 확인 | 3개 |
| `first_step` | 지금 당장 할 일 | 1~2문장 |

## 톤 규칙

1. **약점을 먼저 쓴다.** 칭찬 일색 금지. `trap`은 그 유형이 **실제로 돈을 잃는 지점**이어야 한다.
2. **함정은 유형마다 달라야 한다.** 8개 카드의 `trap`을 나란히 놓았을 때 서로 바꿔 써도 말이 되면 실패다. 예 —
   - 안전·간편·월세 → "편한 물건엔 사람이 몰려 비싸게 낙찰된다"
   - 안전·간편·차익 → "손 안 대면 파는 값도 안 오른다. 낙찰가가 싸야만 성립"
   - 모험·간편·월세 → "서류만 복잡하고 사람은 없는 물건은 드물다"
3. **숫자를 준다.** "예비비를 넉넉히" ✕ / "낙찰가의 5~10%" ○. "회수에 오래 걸린다" ✕ / "보통 3~5년" ○.
4. **감내도를 능력으로 쓰지 않는다.** 간편형(`E`)을 게으르거나 열등하게 묘사하지 않는다. 편한 물건은 **비싸게 사는 대가**를 치른다는 trade-off로 쓴다.
5. **체크리스트는 숫자로 답할 수 있어야 한다.** "시장을 잘 살펴봤는가" ✕ / "같은 단지에서 수리된 집이 실제로 얼마에 팔렸는지 확인했는가" ○.
6. **첫걸음은 실행 가능해야 한다.** "공부하세요" ✕ / "유찰 1회 이상 + 권리 단순 물건 10건을 추려 수익률을 계산해 보세요" ○.
7. **초보 적합도는 유형이 아니라 조합의 문제로.** 어떤 유형도 나쁘지 않다. 경험 없이 어려운 조합에 들어가는 것이 위험할 뿐이다.

## 규제·세금 인용

근거는 오직 `_workspace/00_regulations.md`다. 기억으로 수치를 쓰지 않는다.

- `[불확실]` 표기 항목은 "확인 필요"로 쓰고 단정하지 않는다.
- 경매 특유의 양면을 빠뜨리지 않는다: **대출규제는 경매도 동일, 토지거래허가 실거주의무·자금조달계획서는 경매 면제**(기회이자 고가낙찰 함정).
- 면책은 결과 화면에 항상 노출한다.

## 정합성

- 유형 코드는 `01_typology.md`·`02_diagnostic.json` 정본 그대로. 새 코드를 만들지 않는다.
- `fit`(잘 맞는 물건)이 **검색조건과 모순되면 안 된다.** 예산 5천 구간에 "국민평형 아파트"를 권하면 검색 결과가 0건이 된다. `04_search_criteria.json`의 규칙과 대조한다.
- 현실에서 모순되는 유형 조합을 발견하면 `typology-architect`에게 피드백한다.

## 산출물

- `_workspace/02_diagnostic.json`의 `types[]` — **콘텐츠 정본**(웹이 그대로 렌더링)
- `_workspace/03_profiles.md` — 한눈에 보기 표 + 서술 원칙(사람이 읽는 문서). 문구를 고칠 때는 **JSON을 먼저** 고친다.
